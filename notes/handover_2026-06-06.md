# Handover — Session of 2026-06-06

Purpose: hand a brand-new session the **key decisions, dead-ends, and findings**
of this session, so nobody re-treads the same ground. For the current code state
read `notes/session_summary.md`; this doc is the *why* and the *story*.

---

## Starting point

The project began this session on the **original design**: a mutex *was* the
fork (`pthread_mutex_lock` = pick up fork), asymmetric pickup order, plus a
one-time even-philosopher startup stagger. It mostly worked but `5 800 200 200`
starved a philosopher roughly **5/20** runs.

## What we set out to do

Diagnose and fix the `5 800 200 200` starvation, then validate the whole project
against the **eval sheet** (`ng_4_philosophers.pdf`, decoded this session — its
authoritative test list is now in `session_summary.md`).

---

## Key decisions (in order) and their outcomes

1. **Diagnosed the starvation** as unfair fork hand-off + hold-and-wait: a
   just-fed philosopher re-grabs a shared fork before its starving neighbour,
   because `pthread_mutex_lock` is not FIFO-fair.

2. **Tried a think-delay** (`usleep` after "is thinking") as a fairness/spacing
   fix. A tiny `usleep(500)` was insufficient (still ~4/15). A computed
   half-slack delay helped but never reached zero.

3. **Aryan chose to refactor forks to an integer + mutex** (`int fork_check`
   guarded by a per-fork mutex), reading the subject's "protect the forks' state
   with a mutex" literally. Claude initially pushed back (mutex-as-fork is
   simpler/standard) — this was **resolved in Aryan's favour** later (see #6).

4. **Built an arbitrator + both-or-none version** (single `waiter` mutex, grab
   both forks or neither). Result: **WORSE** — 16/20 with the stagger, 2/20 with
   a think-delay. Conclusion: a busy-wait on a global `waiter` is *less* fair
   than per-fork blocking, because there's no queue — the loser just re-races.

5. **Dropped the startup stagger** — with both-or-none it was redundant and it
   *wasted* an even philosopher's first-meal budget (deaths clustered at ~801).

6. **Aryan's friend's passing repo** (`github.com/AbdullahSayed038/PHILO`)
   settled the design debate: it uses **exactly** the integer + per-fork mutex +
   busy-wait pattern and it **passed evaluation**. So the design is compliant.
   Its details that matter: **no arbitrator**, `usleep(100)` backoff, **one fork
   at a time**, death-checked inside the grab loop. Stress-tested it: it also
   dies ~3/20 on WSL — i.e. the same flakiness, and it still passed.

7. **Refactored to match that proven pattern**: integer `forks[]` + per-fork
   `forks_mutexes[]`, busy-wait `grab_one` with `usleep(100)`, asymmetric order,
   no arbitrator. Result on WSL: **~3/20** — at/under the passing reference.

8. **THE BIG FINDING — most WSL deaths are environmental, not the code.**
   Classifying deaths by the silent gap before them showed 4 of 5 deaths had a
   ~1 s silent gap (the whole VM froze), occurring like clockwork **every ~32 s
   of wall-clock time**. Only ~**1/25** were real (clean-cadence) starvation.
   The Windows host periodically pauses the WSL VM; that inflates the death
   count. On the 42 Linux machine this won't happen. The eval sheet explicitly
   treats such "slow hardware" deaths as defensible.

9. **Final cleanups (Aryan's calls):**
   - **Dropped the think-delay.** On `5 800 200 200` it cut the fork-wait margin
     from 400 ms to 200 ms (cycle 400→600 ms) for no measurable gain (3/20 vs
     4/20). Simpler and marginally safer without it.
   - **Reject `must_eat == 0`** in parsing (was running then exiting 0).
   - **Removed the dead `waiter` mutex** (leftover from the arbitrator — was
     init'd/destroyed but never locked).

## Achievements / final state

- Design: integer forks + per-fork mutex, busy-wait `usleep(100)`, asymmetric
  pickup, no arbitrator, no think-delay, no stagger. (Details in
  `session_summary.md`.)
- **Validated:** clean build (`-Wall -Wextra -Werror -pthread`), **Norminette
  passes**, **valgrind 0 leaks**, **helgrind 0 races**, death-timing ~1 ms.
- All required eval-sheet tests behave correctly.
- Real (non-WSL-noise) starvation rate ~1/25 — at/below a known-passing repo.

## Things proven so we don't redo them

- Arbitrator / both-or-none busy-wait → **worse** (16/20). Don't revive it.
- Larger backoff (`usleep(500)`) → worse than `usleep(100)`. Keep 100.
- Think-delay → neutral-to-harmful here. Don't re-add without new evidence.
- Startup stagger → redundant/harmful with this design. Gone.
- Integer + per-fork mutex + busy-wait → **compliant and passing** (reference
  repo). The "you can't use the integer / can't hold a fork mutex" worry was
  unfounded.
